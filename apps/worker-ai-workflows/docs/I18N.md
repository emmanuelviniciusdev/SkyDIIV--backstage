# Internationalization (i18n)

This worker generates user-facing text (LLM prompts, weather summaries, wardrobe panorama markdown) in the user's preferred language. Language resolution is shared across both workflows.

---

## Supported locales

| Code | Language | Default |
|---|---|---|
| `pt-BR` | Português (Brasil) | Yes |
| `es-PE` | Español (Perú) | |
| `en-US` | English (United States) | |

These codes align with the SkyDIIV web app (`web/lib/i18n/config.ts`) and the `domains` table seeded with type `language`.

---

## How the user's language is resolved

Both workflows call `resolveUserLocale(userId)` at the start of **build-prompt**. The lookup reads `app_preferences.language_id` joined to `domains.name` and maps the domain name to a locale code.

```mermaid
flowchart TD
    START["build-prompt step"] --> RESOLVE["resolveUserLocale"]
    RESOLVE --> QUERY["SELECT domains.name<br/>FROM app_preferences<br/>JOIN domains ON language_id"]
    QUERY --> HAS_PREFS{"app_preferences<br/>row exists?"}
    HAS_PREFS -->|No| DEFAULT["Fallback: pt-BR"]
    HAS_PREFS -->|Yes| MAP{"domains.name"}
    MAP -->|"Português BR"| PT["pt-BR"]
    MAP -->|"Español PE"| ES["es-PE"]
    MAP -->|"English US"| EN["en-US"]
    MAP -->|Unknown| DEFAULT
    PT --> BUILD["Build prompt and user-facing strings"]
    ES --> BUILD
    EN --> BUILD
    DEFAULT --> BUILD
```

### Database model

```mermaid
erDiagram
    users ||--o| app_preferences : "has"
    domains ||--o{ app_preferences : "language_id"

    users {
        uuid id PK
    }

    app_preferences {
        uuid id PK
        uuid user_id FK
        uuid language_id FK
    }

    domains {
        uuid id PK
        string name "Português BR, Español PE, English US"
        string type "language"
        string source "always null for languages"
    }
```

| Table | Column | Purpose |
|---|---|---|
| `app_preferences` | `language_id` | FK to the user's language domain |
| `domains` | `name`, `type` | Language lookup (`type = 'language'`) |

## What is localized per workflow

```mermaid
flowchart LR
    LOCALE["resolveUserLocale"]

    subgraph weekly["generate-weekly-outfits"]
        W1["build-prompt"]
        W2["LLM prompt<br/>instructions + labels"]
        W3["weekly_outfits.weather_summary"]
        W4["LLM JSON keys<br/>sunday…saturday"]
        W1 --> W2
        W1 --> W3
        W2 --> W4
    end

    subgraph panorama["generate-wardrobe-panorama"]
        P1["build-prompt"]
        P2["LLM prompt<br/>sections + labels"]
        P3["wardrobe_panorama.content<br/>markdown"]
        P1 --> P2
        P2 --> P3
    end

    LOCALE --> W1
    LOCALE --> P1

    style W4 fill:#f9f9f9,stroke:#999
```

Legend: shaded nodes are **not** localized (schema-stable English keys).

### generate-weekly-outfits

| Output | Localized? | Notes |
|---|---|---|
| LLM prompt (instructions + data labels) | Yes | Template selected by locale |
| `weekly_outfits.weather_summary` | Yes | Stored in the user's locale |
| LLM JSON weekday keys (`sunday`, …) | No | Schema-stable English keys |

### generate-wardrobe-panorama

| Output | Localized? | Notes |
|---|---|---|
| LLM prompt (instructions + section headers) | Yes | Built by `buildWardrobePanoramaPrompt()` |
| `wardrobe_panorama.content` | Yes | LLM output language follows the prompt locale |
